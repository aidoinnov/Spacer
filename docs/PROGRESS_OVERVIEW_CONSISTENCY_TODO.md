## 목표

현재 깊이에서 확인된 상위 폴더는 하위 분석이 진행되는 동안에도 최신 누적 용량으로 표시한다.
전체 합계와 폴더별 합계가 같은 관측 시점을 사용해야 한다. 모든 깊이의 분석 완료를
기다리거나 전체 트리를 반복 복사하지 않는다. 아직 읽지 않은 디스크 용량은 추정하지 않는다.

개요 갱신 책임만 분리한다. OS 분기는 기존 native port/adapter 내부에 둔다.

## P0 — 계약과 집계 정확성

- [x] `total = 표시 항목 합 + 명시적으로 생략한 관측 용량`을 같은 sequence/scan 세대에서 보장한다.

  큰 파일 순위를 상위 폴더와 같은 지도에 합산하지 않는다.

  생략 항목 수·용량을 전달하고, ‘기타 항목’으로 구별한다. 상한 확대와 무제한 전송은 하지 않는다.

  할당 크기가 0이고 논리 크기만 있는 sparse 파일도 논리 모드에서 누락하지 않는다.
  두 크기 기준 후보를 유지할 경우 각각의 상한과 전송 크기를 명시한다.
- [x] 구형 native progress 입력의 기본값·호환 동작을 정의한다. 구형 입력의 차액은

## P2 — 회귀 테스트와 정량 판정

테스트는 완료 결과뿐 아니라 **모든 관측 진행 이벤트**를 검사한다.
통제된 입력에서는 독립 oracle과 비교한다. OS 타이밍에 의존하는 sleep 대신
가짜 reader/시계·정해진 배치 경계를 우선 사용한다.

| 시나리오 | 판정 기준 |
|---|---|
| 단일 폴더, 노드 100→150→199→200 | 매 이벤트 폴더 합계=관측 합계, 허위 기타 0바이트 |
| 노드 수 고정·폴더 바이트만 증가 | 다음 진행 이벤트에 정확히 반영 |
| 상위 폴더 8개·65,536파일 | 전달 폴더 8개, 폴더만 있는 fixture의 기타 0바이트 |
| 상위 폴더 16개/17개/1,000개 | 상한 준수, 생략 수·용량 정확, 전체 합계 보존 |
| 직속 파일+폴더+중첩 대형 파일 | 각 관측 바이트 한 번만 합산, 중복 0 |
| 논리/할당 순위 역전·sparse·0바이트 | 각 모드 oracle 일치, 유효 후보 누락 0 |
| 깊은 트리·대형 단일 폴더·작은 입력 | 이벤트별 합계 일치, 이전 전체 스캔 결과와 동일 |
| 접근 거부·symlink/reparse·hardlink·mount 경계 | 기존 집계 정책 유지, 가상 미탐색 바이트 0 |
| 취소/오류/새 스캔/완료 전환 | 세대 혼합 0, 종료 후 소유 자원 잔류 0 |
| 구형/신형 wire·필드 누락·잘못된 합계 | 호환 표시 또는 명시적 진단, panic/중복 합산 0 |

- [x] Swift accumulator 테스트: 중간 이벤트의 폴더 freshness, 후보 탈락/재진입·동률·논리 기준.
- [x] Mac 실제 backend wire 테스트: 8개 폴더 전송부터 Rust 모델 해석까지 확인.
- [x] Windows fake reader 단위 테스트 + Windows 실제 native wire 검증을 구분해 기록.
- [x] Rust layout 테스트: 합계·잔여 의미·모드 전환·구형 입력·탐색 가능 여부.
